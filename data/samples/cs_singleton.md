## CS - 싱글톤 패턴

## 1. 한 줄 요약

싱글톤 패턴은 클래스의 인스턴스를 오직 하나만 생성되도록 제한하고, 어디서든 그 인스턴스에 접근할 수 있도록 하는 디자인 패턴이다.

## 2. 왜 필요한가? (Why)

- **유일성 보장**: 시스템 내에서 특정 클래스의 인스턴스가 오직 하나만 존재해야 할 때 유용하다. 예를 들어, 설정 관리자, 로깅 시스템, 데이터베이스 연결 풀 등이 있다.
- **전역 접근**: 전역 변수를 사용하는 것보다 안전하게 전역적인 접근을 제공한다. 싱글톤은 필요할 때만 인스턴스를 생성하고, 클래스 내부에서 인스턴스 생성을 제어할 수 있다.
- **자원 관리**: 특정 자원에 대한 접근을 제어하고, 자원 낭비를 방지할 수 있다.

## 3. 핵심 개념 (What)

- **private 생성자**: 외부에서 인스턴스를 생성하는 것을 막기 위해 생성자를 private으로 선언한다.
- **static 멤버 변수**: 클래스 내부에 자신의 유일한 인스턴스를 저장하는 static 멤버 변수를 선언한다.
- **static getInstance() 메서드**: 유일한 인스턴스에 접근할 수 있는 static 메서드를 제공한다. 이 메서드는 인스턴스가 아직 생성되지 않았을 경우에만 인스턴스를 생성하고, 이미 생성된 인스턴스를 반환한다. => static 유일한 인스턴스 반환 가능, 레퍼런스 반환 이유는 복사나 동적할당 피하고 동일한 인스턴스 참조 가능

## 4. 동작 과정 (How)

1. 클래스의 생성자를 private으로 선언하여 외부에서의 직접적인 인스턴스 생성을 막는다.
2. 클래스 내부에 static 멤버 변수로 자신의 유일한 인스턴스를 저장한다. 이 변수는 프로그램 시작 시 초기화되거나, 처음 `getInstance()` 메서드가 호출될 때 초기화된다.
3. `getInstance()` 메서드를 통해 유일한 인스턴스에 접근한다. 이 메서드는 인스턴스가 아직 생성되지 않았을 경우에만 인스턴스를 생성하고, 이미 생성된 인스턴스를 반환한다.

```cpp
class Singleton {
private:
    Singleton() {} // private 생성자
    static Singleton* instance; // static 멤버 변수
//Lazy 
public:
    static Singleton* getInstance() {
        if (instance == nullptr) {
            instance = new Singleton(); // 인스턴스가 없으면 생성
        }
        return instance; // 인스턴스 반환
    }
};

Singleton* Singleton::instance = nullptr; // static 멤버 변수 초기화
```

## 5. 장단점 / 트레이드오프

- **장점**:
  - 유일한 인스턴스 보장
  - 전역적인 접근 제공
  - 필요할 때만 인스턴스 생성
- **단점**:
  - 과도하게 사용하면 전역 변수와 유사한 문제 발생 (테스트 어려움, 의존성 증가)
  - 멀티스레드 환경에서 동기화 문제 발생 가능 (thread-safe하게 구현해야 함)
  - 객체지향 설계 원칙 위배 가능성 (단일 책임 원칙)

## 6. 자주 나오는 질문 / 오해

- **Q**: 싱글톤 패턴은 전역 변수와 어떻게 다른가?
  - **A**: 싱글톤은 클래스 내부에서 인스턴스 생성을 제어하고, 필요할 때만 인스턴스를 생성한다. 반면, 전역 변수는 프로그램 시작 시 항상 생성된다. 또한, 싱글톤은 객체지향적인 방식으로 구현할 수 있으며, 상속이나 인터페이스 구현 등의 기능을 활용할 수 있다.
- **Q**: 싱글톤 패턴을 멀티스레드 환경에서 안전하게 사용하는 방법은?
  - **A**: 멀티스레드 환경에서는 여러 스레드가 동시에 `getInstance()` 메서드를 호출하여 인스턴스를 여러 번 생성할 수 있다. 이를 방지하기 위해 lock을 사용하여 동기화하거나, Meyers Singleton (static initialization) 방식을 사용할 수 있다.

## 7. 프로젝트에서 어디에 쓰일 수 있는가

- **설정 관리자**: 애플리케이션의 설정을 관리하는 클래스를 싱글톤으로 구현하여 어디서든 설정에 접근할 수 있도록 한다.
- **로깅 시스템**: 로깅 기능을 제공하는 클래스를 싱글톤으로 구현하여 모든 클래스에서 로깅 기능을 사용할 수 있도록 한다.
- **게임 엔진**: 게임 엔진에서 리소스 관리자, 입력 관리자 등을 싱글톤으로 구현하여 게임 내에서 일관된 접근을 제공한다.
